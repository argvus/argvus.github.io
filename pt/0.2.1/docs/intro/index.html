Introdução

This content is for v0.2.1. Switch to the latest version for up-to-date documentation.

Ambiente de Desktop ARGVUS

Seção intitulada “Ambiente de Desktop ARGVUS”

O ARGVUS é um ambiente de desktop completo e pronto para uso, construído em torno do Hyprland e empacotado nativamente para Arch Linux.

O ARGVUS não é uma distribuição Linux, um repositório de configuração do Hyprland nem uma coleção de dotfiles pessoais. É um ambiente de desktop integrado que detém a sessão do usuário, define a experiência do desktop, fornece infraestrutura de desktop e componentes nativos, e integra aplicações upstream selecionadas quando desenvolver uma substituição específica do ARGVUS traria pouco benefício.

O Hyprland é o compositor usado pelo ARGVUS. O Arch Linux é a plataforma de sistema operacional na qual o ARGVUS é atualmente empacotado e suportado.

De forma simplificada:

A distinção é intencional:

O Arch Linux fornece o sistema operacional. O ARGVUS fornece o ambiente de desktop. O Hyprland fornece o compositor.

Por que o ARGVUS é um ambiente de desktop

Seção intitulada “Por que o ARGVUS é um ambiente de desktop”

Não existe um requisito de que um ambiente de desktop precise desenvolver todas as aplicações que rodam dentro dele.

Projetos como GNOME e KDE são mais do que ambientes de desktop: com o tempo desenvolveram também grandes ecossistemas de aplicações, frameworks, bibliotecas, utilitários e plataformas de desenvolvimento. Aplicações como gerenciadores de arquivos, terminais, editores de texto, visualizadores de imagens e leitores de documentos fortalecem esses ecossistemas, mas deter substitutos para cada categoria de aplicação não é o que fundamentalmente define um ambiente de desktop.

Um ambiente de desktop é responsável principalmente pela sessão gráfica do usuário e por apresentar um ambiente integrado no qual as aplicações rodam.

Isso inclui responsabilidades como:

  • estabelecer e identificar a sessão gráfica do desktop;
  • iniciar o compositor e o desktop;
  • definir o shell do desktop e seu modelo de interação;
  • fornecer painéis, lançadores, menus e superfícies do sistema;
  • gerenciar aparência e configuração geral do desktop;
  • integrar autenticação, contas, armazenamento e ações de sessão;
  • expor padrões e associações de aplicação coerentes;
  • integrar serviços de sistema necessários ao ambiente gráfico;
  • fornecer um modelo consistente de configuração e theming;
  • definir como o ambiente inicia, roda e termina.

O ARGVUS executa essas responsabilidades como um projeto integrado.

Isso é diferente de instalar o Hyprland e adicionar alguns arquivos de configuração não relacionados.

O ARGVUS não é apenas o Hyprland

Seção intitulada “O ARGVUS não é apenas o Hyprland”

O Hyprland é um compositor Wayland. É uma parte importante do ARGVUS, mas não é o desktop inteiro.

O ARGVUS constrói um desktop ao redor dele.

Conceitualmente:

O compositor gerencia janelas, saídas, workspaces e a composição Wayland. O ARGVUS define o ambiente mais amplo ao redor dele.

Substituir o Hyprland seria uma mudança arquitetural no ARGVUS, mas usar o Hyprland não torna o ARGVUS meramente uma configuração do Hyprland, assim como construir um desktop sobre componentes de sistema existentes não torna o desktop idêntico a esses componentes.

A sessão ARGVUS

Seção intitulada “A sessão ARGVUS”

O projeto argvus-session fornece a infraestrutura de inicialização do Ambiente de Desktop ARGVUS.

Ele entrega:

O arquivo argvus.desktop registra o ARGVUS como uma sessão de desktop Wayland instalável.

O caminho de inicialização gráfica é aproximadamente:

O argvus-session não é simplesmente um wrapper que executa o Hyprland.

Ele prepara o ambiente de sessão do ARGVUS antes de transferir o controle para o argvus-start. Entre outras responsabilidades, a infraestrutura de sessão estabelece o ambiente de configuração usado pelo desktop e torna os padrões do ARGVUS empacotados descobertos pela hierarquia de configuração XDG.

Os pacotes do ARGVUS não precisam copiar toda a sua configuração para o diretório home do usuário. Em vez disso, os padrões empacotados podem permanecer em /usr/share/argvus, enquanto a configuração de propriedade do usuário permanece como uma sobreposição explícita.

O modelo de configuração é:

Para aplicações que suportam configuração de sistema XDG, a sessão adiciona /usr/share/argvus ao caminho de busca de configuração XDG apropriado, preservando diretórios normais de sistema como /etc/xdg.

Isso torna a descoberta de configuração parte da arquitetura de sessão do ARGVUS, em vez de uma coleção de arquivos copiados uma vez para $HOME.

Inicialização e validação da sessão

Seção intitulada “Inicialização e validação da sessão”

O argvus-start estabelece a sessão gráfica e lança o Hyprland com a configuração apropriada do ARGVUS.

A infraestrutura de sessão também lida com preocupações práticas de inicialização do desktop, como seleção e validação de configuração, identidade da sessão gráfica, tratamento de máquina virtual e evitar que estado do ambiente de login vaze para a sessão de desktop do usuário.

Uma sobreposição Hyprland do usuário pode ser usada quando disponível, enquanto a configuração ARGVUS empacotada permanece como fallback do sistema.

Conceitualmente:

Isso é infraestrutura de sessão de desktop: o ARGVUS está decidindo como sua sessão de desktop suportada é montada e iniciada.

Suporte a sessão via TTY

Seção intitulada “Suporte a sessão via TTY”

O argvus-tty permite que a mesma sessão de desktop ARGVUS seja iniciada sem um display manager.

Esse caminho lida com a configuração de sessão adicional necessária ao entrar em um desktop gráfico a partir de um TTY, incluindo integração com o ambiente de login/sessão.

Com isso, o ARGVUS não está amarrado a um display manager específico. A sessão ARGVUS permanece o mesmo desktop, seja selecionada por meio de um greeter gráfico ou acessada pelo lançador TTY suportado.

Infraestrutura de sessão versus um supervisor de sessão completo

Seção intitulada “Infraestrutura de sessão versus um supervisor de sessão completo”

O argvus-session atual deve ser entendido como a infraestrutura de sessão e o bootstrap de sessão do ARGVUS.

Ele prepara e inicia o desktop, mas o ARGVUS não afirma que atualmente fornece um grande gerenciador de sessão monolítico equivalente em escopo a projetos como o gnome-session.

Alguns componentes do desktop ainda podem ser iniciados ou coordenados por meio da configuração do Hyprland e de hooks de inicialização do ARGVUS.

Isso não impede o ARGVUS de ser um ambiente de desktop. Simplesmente identifica uma área em que a arquitetura pode continuar a evoluir.

Isso fortaleceria a supervisão de processos e o gerenciamento do ciclo de vida, mas é uma evolução arquitetural, e não um pré-requisito para que o ARGVUS seja considerado um ambiente de desktop.

O Greeter ARGVUS

Seção intitulada “O Greeter ARGVUS”

O argvus-greeter é o frontend gráfico de login desenvolvido para o Ambiente de Desktop ARGVUS.

É uma aplicação nativa GTK4 escrita para o greetd.

Sua arquitetura é aproximadamente:

O greeter deliberadamente não inicia o desktop normal do usuário antes da autenticação.

Em vez disso, ele roda dentro de um ambiente Wayland mínimo dedicado. Após a autenticação bem-sucedida, o greeter encerra, o compositor temporário é parado e o greetd entrega o controle à sessão de desktop real selecionada.

O greeter também se integra a outras partes do ambiente ARGVUS, incluindo metadados de conta e tratamento de avatares.

Isso dá ao projeto um caminho coerente do login ao desktop:

Um greeter personalizado não é necessário para algo ser um ambiente de desktop, mas no ARGVUS é outro exemplo do projeto deter e integrar a experiência de desktop completa, em vez de meramente distribuir configuração de compositor.

Um ambiente de desktop não precisa de seu próprio gerenciador de arquivos ou terminal

Seção intitulada “Um ambiente de desktop não precisa de seu próprio gerenciador de arquivos ou terminal”

O ARGVUS usa intencionalmente aplicações upstream para algumas tarefas de propósito geral.

Um gerenciador de arquivos, emulador de terminal, navegador, editor de texto, reprodutor de mídia ou visualizador de imagens é uma aplicação que roda dentro do ambiente de desktop. Essas aplicações podem ser desenvolvidas pelo mesmo projeto do desktop, mas não precisam ser.

Por exemplo:

Substituir uma aplicação de propósito geral não muda a identidade do desktop.

Por exemplo:

não faz com que a sessão, o shell, as configurações, os temas, os serviços ou o modelo de desktop do ARGVUS deixem de ser ARGVUS.

Essa separação é útil porque permite que o projeto concentre o esforço de desenvolvimento nos componentes que definem a experiência do desktop, ao mesmo tempo que integra software upstream maduro para funções de aplicação genéricas.

O projeto segue, portanto, um princípio prático:

O ARGVUS desenvolve os componentes que definem a experiência de desktop ARGVUS e integra aplicações upstream de alta qualidade onde reinventá-las não melhoraria de forma significativa o desktop.

Desenvolver um argvus-files, argvus-terminal ou uma suíte completa de aplicações no futuro é possível, mas essas aplicações expandiriam o ecossistema ARGVUS. Elas não são um requisito que precisa ser cumprido antes de o ARGVUS ser considerado um ambiente de desktop.

Ambiente de desktop versus ecossistema de aplicações

Seção intitulada “Ambiente de desktop versus ecossistema de aplicações”

Projetos grandes geralmente combinam várias camadas sob um único nome.

Por exemplo, um projeto maduro de desktop pode conter:

A existência de todas essas camadas torna um ecossistema maior e mais maduro, mas o ecossistema de aplicações não deve ser confundido com a definição do próprio ambiente de desktop.

O ARGVUS atualmente foca primeiro na camada de ambiente de desktop.

Seu ecossistema de aplicações pode crescer independentemente ao longo do tempo.

ARGVUS versus dotfiles ou um “rice”

Seção intitulada “ARGVUS versus dotfiles ou um “rice””

Um conjunto de dotfiles do Hyprland geralmente configura um compositor já existente e uma coleção de aplicações.

Conceitualmente:

O ARGVUS tem uma arquitetura diferente:

A distinção importante é a propriedade.

Com dotfiles comuns, o usuário detém uma coleção configurada de programas independentes.

Com o ARGVUS, o projeto define uma sessão de desktop suportada, empacota seus componentes, estabelece precedência de configuração, fornece infraestrutura de desktop e publica esses componentes como um ambiente coordenado.

É por isso que o ARGVUS é descrito com mais precisão como um ambiente de desktop do que como um projeto de rice ou dotfiles.

ARGVUS versus uma distribuição Linux

Seção intitulada “ARGVUS versus uma distribuição Linux”

O ARGVUS também não é uma distribuição Linux.

Uma distinção útil é:

Um ambiente de desktop controla a experiência gráfica do usuário e a sessão do usuário. Uma distribuição Linux controla a plataforma do sistema operacional e seu ciclo de vida.

O ARGVUS atualmente parte de uma instalação Arch Linux existente.

O Arch permanece responsável pela base do sistema operacional, incluindo os pacotes centrais de sistema e o modelo normal de atualização do sistema.

O ARGVUS é então instalado como o ambiente de desktop.

O ARGVUS atualmente não se define por meio de seu próprio ISO de instalação, instalador de sistema operacional, fork da base do sistema, política de kernel, política de bootloader ou ciclo de vida de sistema operacional independente.

Essas são responsabilidades de nível de distribuição.

O projeto, em vez disso, deixa intencionalmente essas responsabilidades para o Arch Linux.

O repositório de pacotes ARGVUS não torna o ARGVUS uma distribuição

Seção intitulada “O repositório de pacotes ARGVUS não torna o ARGVUS uma distribuição”

O ARGVUS publica pacotes Arch assinados por meio de seu próprio repositório de pacotes.

Esse repositório existe para distribuir os componentes do ARGVUS e pacotes selecionados necessários ao ambiente.

Ter um repositório de pacotes por si só não cria uma distribuição Linux.

Um pacote Arch pode depender de pacotes dos repositórios oficiais do Arch. O pacman resolve essas dependências entre os repositórios configurados.

Conceitualmente:

A regra preferida de empacotamento é simples:

Se um pacote adequado já existe nos repositórios oficiais do Arch e o ARGVUS não precisa modificá-lo, o ARGVUS deve depender desse pacote em vez de republicá-lo.

O repositório ARGVUS deve conter principalmente software de propriedade do ARGVUS, pacotes que exigem alterações específicas do ARGVUS e software de terceiros selecionado que não possa ser obtido de forma razoável dos repositórios Arch suportados.

Isso mantém a fronteira de responsabilidade clara:

Fronteira de responsabilidade

Seção intitulada “Fronteira de responsabilidade”

A arquitetura pretendida do projeto pode ser resumida da seguinte forma:

Camada Responsabilidade principal
Linux Kernel e fundação de sistema operacional de baixo nível
Arch Linux Sistema operacional, base de pacotes e ciclo de vida do sistema
Wayland Protocolo de exibição

Componentes nativos e integrados

Seção intitulada “Componentes nativos e integrados”

O ARGVUS é dividido em pacotes e repositórios focados, em vez de um único pacote monolítico.

Os componentes atuais do projeto incluem:

  • argvus — a camada principal de configuração e integração do desktop;
  • argvus-session — infraestrutura de sessão gráfica e inicialização via TTY do ARGVUS;
  • argvus-appearance — recursos de aparência compartilhados, como wallpapers e fontes;
  • argvus-storage — integração de armazenamento removível;
  • argvus-calendar — integração nativa de calendário;
  • argvus-default-apps — gerenciamento de aplicações padrão;
  • argvus-accounts — metadados de conta local e integração de avatares;
  • argvus-greeter — greeter de login GTK4 para o greetd;
  • argvus-waybar — integração e empacotamento Waybar do ARGVUS;
  • argvus-splash — experiência de boot Plymouth do ARGVUS;
  • argvus-extras — pacotes adicionais selecionados usados pelo ambiente.

O ARGVUS também integra projetos upstream, como:

  • Hyprland;
  • Waybar;
  • Rofi;
  • Wofi;
  • Quickshell;
  • emuladores de terminal, gerenciadores de arquivos e outras aplicações de propósito geral.

Um componente upstream integrado não se torna software desenvolvido pelo ARGVUS. O ARGVUS deve preservar essa distinção em sua documentação e atribuição.

O que o ARGVUS detém é o ambiente no qual esses componentes são selecionados, configurados e integrados.

Foco do projeto

Seção intitulada “Foco do projeto”

O ARGVUS é intencionalmente focado como um ambiente de desktop para Arch Linux.

O projeto não precisa se tornar uma distribuição Linux para fornecer uma experiência de instalação completa no Arch, e não precisa criar substitutos para cada aplicação de desktop para se qualificar como ambiente de desktop.

Sua prioridade de desenvolvimento é a camada que diferencia a experiência ARGVUS:

As aplicações de propósito geral podem continuar vindo de projetos upstream, a menos que uma aplicação específica do ARGVUS tenha um motivo claro para existir.

Isso mantém o projeto gerenciável e dá a ele uma identidade clara.

Definição

Seção intitulada “Definição”

A descrição preferida do projeto é:

O ARGVUS é um ambiente de desktop completo baseado em Hyprland para Arch Linux.

Uma descrição mais arquitetural é:

O ARGVUS é um ambiente de desktop que detém a sessão gráfica e a experiência de desktop, usa o Hyprland como seu compositor Wayland, integra serviços nativos do ARGVUS e aplicações upstream selecionadas, e é empacotado nativamente para Arch Linux.

A primeira frase é adequada para páginas do projeto e descrições curtas. A segunda explica a fronteira técnica com precisão.

Status de desenvolvimento

Seção intitulada “Status de desenvolvimento”

O ARGVUS está em desenvolvimento ativo.

A arquitetura atual já estabelece uma sessão de desktop Wayland distinta e um conjunto crescente de componentes ARGVUS coordenados. Algumas partes do ambiente ainda dependem de software upstream ou de coordenação de inicialização fornecida pela configuração do Hyprland, e essas fronteiras podem continuar a evoluir à medida que o projeto amadurece.

Esse status de desenvolvimento não muda a categoria pretendida do projeto.

O ARGVUS é desenvolvido como um ambiente de desktop, não como uma distribuição Linux.
