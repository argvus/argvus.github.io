Introdução

This content is for v0.3.0. Switch to the latest version for up-to-date documentation.

Ambiente de Desktop ARGVUS

Seção intitulada “Ambiente de Desktop ARGVUS”

O ARGVUS é um ambiente de desktop completo e pronto para uso, construído em torno do Hyprland e empacotado nativamente para Arch Linux.

O ARGVUS não é uma distribuição Linux, um repositório de configuração do Hyprland nem uma coleção de dotfiles pessoais. É um ambiente de desktop integrado que detém a sessão gráfica do usuário, gerencia o ciclo de vida de seus componentes essenciais de desktop, define a experiência do desktop, fornece infraestrutura nativa de desktop e integra aplicações upstream selecionadas quando desenvolver uma substituição específica do ARGVUS traria pouco benefício.

O Hyprland é o compositor Wayland usado pelo ARGVUS. O Arch Linux é a plataforma de sistema operacional na qual o ARGVUS é atualmente empacotado e suportado.

De forma simplificada:

A distinção é intencional:

O Arch Linux fornece o sistema operacional. O ARGVUS fornece o ambiente de desktop. O Hyprland fornece o compositor.

Por que o ARGVUS é um ambiente de desktop

Seção intitulada “Por que o ARGVUS é um ambiente de desktop”

Não existe um requisito de que um ambiente de desktop precise desenvolver todas as aplicações que rodam dentro dele.

Projetos como GNOME e KDE são mais do que ambientes de desktop: com o tempo desenvolveram também grandes ecossistemas de aplicações, frameworks, bibliotecas, utilitários e plataformas de desenvolvimento. Aplicações como gerenciadores de arquivos, terminais, editores de texto, visualizadores de imagens e leitores de documentos fortalecem esses ecossistemas, mas deter substitutos para cada categoria de aplicação não é o que fundamentalmente define um ambiente de desktop.

Um ambiente de desktop é responsável principalmente pela sessão gráfica do usuário e por apresentar um ambiente integrado no qual as aplicações rodam.

Isso inclui responsabilidades como:

  • estabelecer e identificar a sessão gráfica do desktop;
  • iniciar e encerrar a sessão do desktop;
  • gerenciar o ciclo de vida dos processos essenciais do desktop;
  • definir o shell do desktop e seu modelo de interação;
  • fornecer painéis, lançadores, menus e superfícies do sistema;
  • gerenciar aparência e configuração geral do desktop;
  • integrar autenticação, contas, armazenamento e ações de sessão;
  • expor padrões e associações de aplicação coerentes;
  • integrar serviços de sistema necessários ao ambiente gráfico;
  • fornecer um modelo consistente de configuração e theming;
  • supervisionar serviços do desktop e recuperá-los quando apropriado;
  • garantir que os processos de propriedade da sessão sejam limpos no logout.

O ARGVUS executa essas responsabilidades como um projeto integrado.

Isso é diferente de instalar o Hyprland e adicionar alguns arquivos de configuração não relacionados.

O ARGVUS não é apenas o Hyprland

Seção intitulada “O ARGVUS não é apenas o Hyprland”

O Hyprland é um compositor Wayland. É uma parte importante do ARGVUS, mas não é o desktop inteiro.

O ARGVUS constrói e gerencia um desktop ao redor dele.

Conceitualmente:

O compositor gerencia janelas, saídas, workspaces e a composição Wayland.

O ARGVUS detém o ambiente mais amplo ao redor dele: ciclo de vida da sessão, configuração, serviços de desktop, componentes do shell, supervisão de processos, aparência, integração e comportamento voltado ao usuário.

Substituir o Hyprland seria uma mudança arquitetural no ARGVUS, mas usar o Hyprland não torna o ARGVUS meramente uma configuração do Hyprland.

O Gerenciador de Sessão ARGVUS

Seção intitulada “O Gerenciador de Sessão ARGVUS”

O projeto argvus-session fornece a infraestrutura de ciclo de vida e supervisão de sessão do Ambiente de Desktop ARGVUS.

Ele é responsável por criar o ambiente gráfico ARGVUS, preparar seu estado de execução, lançar o compositor, coordenar os componentes essenciais do desktop e limpá-los quando a sessão termina.

O caminho de inicialização gráfica é aproximadamente:

O argvus-session é, portanto, mais do que um lançador do Hyprland.

É a camada que define o ciclo de vida da sessão de desktop ARGVUS.

Supervisão de sessão

Seção intitulada “Supervisão de sessão”

O ARGVUS usa o systemd --user como supervisor de processos dos componentes persistentes que pertencem à sessão do desktop.

Em vez de iniciar processos de desktop de longa duração por meio de padrões como:

o gerenciador de sessão atribui a propriedade dos processos a serviços de usuário.

Conceitualmente:

Isso fornece:

  • propriedade explícita de processos;
  • ordenação de dependências e inicialização;
  • políticas de reinício;
  • registro centralizado por meio do journal;
  • desligamento limpo da sessão;
  • proteção contra processos duplicados acidentais;
  • separação entre serviços de propriedade do ARGVUS e processos de usuário não relacionados.

O gerenciador de sessão não precisa reinventar esses recursos dentro de um daemon monolítico personalizado. O ARGVUS define a arquitetura da sessão enquanto o systemd --user fornece o mecanismo de supervisão subjacente.

O target de sessão ARGVUS

Seção intitulada “O target de sessão ARGVUS”

O desktop em execução é representado por um target de usuário específico do ARGVUS.

Conceitualmente:

O target representa o tempo de vida da sessão gráfica ARGVUS.

Os componentes que pertencem à sessão estão vinculados a esse ciclo de vida em vez de serem habilitados globalmente para todos os ambientes de desktop que o usuário possa executar.

Com isso, entrar no GNOME, no KDE Plasma, no Hyprland puro, no Sway ou em outro ambiente não inicia automaticamente os serviços de desktop específicos do ARGVUS.

Seção intitulada “Preparação da sessão”

Nem toda tarefa de inicialização precisa permanecer como um processo persistente.

O ARGVUS separa a preparação one-shot da sessão dos serviços de longa duração.

Essas operações são aplicadas antes que os serviços persistentes dependentes sejam iniciados.

Essa separação evita misturar trabalho de configuração com supervisão de processos.

Gerenciamento de ambiente

Seção intitulada “Gerenciamento de ambiente”

O gerenciador de sessão estabelece o ambiente usado pelo ARGVUS e o propaga ao gerenciador de serviços do usuário e ao ambiente de ativação de D-Bus quando necessário.

Isso inclui a hierarquia de configuração XDG do desktop e os caminhos de execução específicos do ARGVUS.

Os pacotes do ARGVUS não precisam copiar toda a sua configuração para o diretório home do usuário.

O modelo de configuração permanece:

Para aplicações que suportam configuração de sistema XDG, /usr/share/argvus participa da hierarquia de busca de configuração enquanto a configuração normal de sistema, como /etc/xdg, permanece disponível.

Isso torna a descoberta de configuração parte da arquitetura da sessão, em vez de uma coleção de dotfiles copiados uma vez para $HOME.

Inicialização e prontidão do Hyprland

Seção intitulada “Inicialização e prontidão do Hyprland”

O Hyprland permanece o compositor do Ambiente de Desktop ARGVUS.

O gerenciador de sessão é responsável por lançá-lo com o ambiente ARGVUS suportado e as regras de configuração.

O ARGVUS preserva:

  • sobreposições Hyprland do usuário;
  • configuração de fallback empacotada;
  • validação de configuração;
  • detecção de máquina virtual e soluções alternativas;
  • ambiente correto da sessão gráfica;
  • suporte a display manager;
  • suporte a sessão via TTY.

Assim que o compositor está pronto, o target de desktop ARGVUS é iniciado e os serviços de desktop supervisionados ficam ativos.

Conceitualmente:

O Hyprland é, portanto, o compositor dentro da sessão, não o dono do ciclo de vida dos processos do desktop.

Desligamento da sessão

Seção intitulada “Desligamento da sessão”

O gerenciador de sessão também é dono do caminho de desligamento.

Quando a sessão gráfica ARGVUS termina:

Os componentes persistentes do ARGVUS não permanecem órfãos após o logout.

Esse ciclo de vida explícito é uma das principais diferenças entre um ambiente de desktop gerenciado e uma coleção de comandos de inicialização.

Recarregando o desktop

Seção intitulada “Recarregando o desktop”

As recargas do desktop também são tratadas como operações de sessão, em vez de matar processos indiscriminadamente.

Uma recarga pode reaplicar configuração mutável e recarregar ou reiniciar seletivamente apenas os componentes que exigem isso.

Conceitualmente:

Isso preserva a sessão gráfica do usuário mantendo a propriedade dos processos sob o gerenciador de sessão.

Suporte a sessão via TTY

Seção intitulada “Suporte a sessão via TTY”

O argvus-tty permite que o mesmo Ambiente de Desktop ARGVUS seja iniciado sem um display manager gráfico.

Esse caminho realiza a integração adicional necessária ao entrar no ambiente gráfico a partir de um TTY e, em última instância, lança o mesmo ciclo de vida de sessão ARGVUS.

Conceitualmente:

O ARGVUS não está, portanto, amarrado a um display manager específico.

O Greeter ARGVUS

Seção intitulada “O Greeter ARGVUS”

O argvus-greeter é o frontend gráfico de login desenvolvido para o Ambiente de Desktop ARGVUS.

É uma aplicação nativa GTK4 escrita para o greetd.

Sua arquitetura é aproximadamente:

O greeter deliberadamente não inicia o desktop normal do usuário antes da autenticação.

Em vez disso, ele roda dentro de um ambiente Wayland mínimo dedicado. Após a autenticação bem-sucedida, o ambiente temporário do greeter termina e o greetd entrega o controle à sessão de desktop real selecionada.

O caminho ARGVUS completo é, portanto:

Um greeter personalizado não é necessário para algo ser um ambiente de desktop, mas no ARGVUS é outro exemplo do projeto deter e integrar a experiência completa do login ao logout.

Um ambiente de desktop não precisa de seu próprio gerenciador de arquivos ou terminal

Seção intitulada “Um ambiente de desktop não precisa de seu próprio gerenciador de arquivos ou terminal”

O ARGVUS usa intencionalmente aplicações upstream para algumas tarefas de propósito geral.

Um gerenciador de arquivos, emulador de terminal, navegador, editor de texto, reprodutor de mídia ou visualizador de imagens é uma aplicação que roda dentro do ambiente de desktop.

Essas aplicações podem ser desenvolvidas pelo mesmo projeto do desktop, mas não precisam ser.

Por exemplo:

Substituir uma aplicação de propósito geral não muda a identidade do desktop.

Por exemplo:

não faz com que a sessão, o shell, as configurações, os serviços, os temas ou o modelo de desktop do ARGVUS deixem de ser ARGVUS.

Essa separação permite que o projeto concentre o esforço de desenvolvimento nos componentes que definem a experiência do desktop, ao mesmo tempo que integra software upstream maduro para funções de aplicação genéricas.

O projeto segue, portanto, um princípio prático:

O ARGVUS desenvolve os componentes que definem a experiência de desktop ARGVUS e integra aplicações upstream de alta qualidade onde reinventá-las não melhoraria de forma significativa o desktop.

Desenvolver um argvus-files, argvus-terminal ou uma suíte mais ampla de aplicações no futuro é possível, mas essas aplicações expandiriam o ecossistema ARGVUS. Elas não são um pré-requisito para o ARGVUS ser um ambiente de desktop.

Ambiente de desktop versus ecossistema de aplicações

Seção intitulada “Ambiente de desktop versus ecossistema de aplicações”

Projetos grandes de desktop geralmente combinam várias camadas sob um único nome.

Por exemplo:

A existência de todas essas camadas torna um ecossistema maior e mais maduro, mas o ecossistema de aplicações não deve ser confundido com a definição do próprio ambiente de desktop.

O ARGVUS atualmente foca primeiro na camada de ambiente de desktop.

Seu ecossistema de aplicações pode crescer independentemente ao longo do tempo.

ARGVUS versus dotfiles ou um “rice”

Seção intitulada “ARGVUS versus dotfiles ou um “rice””

Um conjunto de dotfiles do Hyprland geralmente configura um compositor já existente e uma coleção de aplicações.

Conceitualmente:

O ARGVUS tem uma arquitetura diferente:

A distinção importante é a propriedade.

Com dotfiles comuns, o usuário detém uma coleção configurada de programas independentes.

Com o ARGVUS, o projeto define uma sessão de desktop suportada, empacota seus componentes, estabelece precedência de configuração, supervisiona os processos essenciais e publica esses componentes como um ambiente coordenado.

É por isso que o ARGVUS é descrito com mais precisão como um ambiente de desktop do que como um projeto de rice ou dotfiles.

ARGVUS versus uma distribuição Linux

Seção intitulada “ARGVUS versus uma distribuição Linux”

O ARGVUS também não é uma distribuição Linux.

Uma distinção útil é:

Um ambiente de desktop controla a experiência gráfica do usuário e a sessão do usuário. Uma distribuição Linux controla a plataforma do sistema operacional e seu ciclo de vida.

O ARGVUS parte de uma instalação Arch Linux existente.

O Arch permanece responsável pela base do sistema operacional, incluindo os pacotes centrais de sistema e o modelo normal de atualização do sistema.

O ARGVUS é então instalado como o ambiente de desktop.

O ARGVUS não se define por meio de seu próprio instalador de sistema operacional, fork da base do sistema, política de kernel, política de bootloader ou ciclo de vida de sistema operacional independente.

Essas são responsabilidades de nível de distribuição.

O projeto deixa intencionalmente essas responsabilidades para o Arch Linux.

O repositório de pacotes ARGVUS não torna o ARGVUS uma distribuição

Seção intitulada “O repositório de pacotes ARGVUS não torna o ARGVUS uma distribuição”

O ARGVUS publica pacotes Arch assinados por meio de seu próprio repositório de pacotes.

Esse repositório existe para distribuir os componentes do ARGVUS e pacotes selecionados necessários ao ambiente.

Ter um repositório de pacotes por si só não cria uma distribuição Linux.

Um pacote Arch pode depender de pacotes dos repositórios oficiais do Arch. O pacman resolve essas dependências entre os repositórios configurados.

Conceitualmente:

A regra preferida de empacotamento é:

Se um pacote adequado já existe nos repositórios oficiais do Arch e o ARGVUS não precisa modificá-lo, o ARGVUS deve depender desse pacote em vez de republicá-lo.

O repositório ARGVUS deve conter principalmente software de propriedade do ARGVUS, pacotes que exigem alterações específicas do ARGVUS e software de terceiros selecionado que não possa ser obtido de forma razoável dos repositórios Arch suportados.

Isso mantém a fronteira de responsabilidade clara:

Fronteira de responsabilidade

Seção intitulada “Fronteira de responsabilidade”

A arquitetura pretendida do projeto pode ser resumida da seguinte forma:

Camada Responsabilidade principal
Linux Kernel e fundação de sistema operacional de baixo nível

ARGVUS Ciclo de vida da sessão de desktop, supervisão de processos, experiência de desktop, integração e serviços de desktop
Aplicações Cargas de trabalho do usuário rodando dentro do desktop ARGVUS

Manter essa separação permite que o ARGVUS permaneça um projeto de desktop focado.

Componentes nativos e integrados

Seção intitulada “Componentes nativos e integrados”

O ARGVUS é dividido em pacotes e repositórios focados, em vez de um único pacote monolítico.

Os componentes atuais do projeto incluem:

  • argvus — a camada principal de configuração e integração do desktop;
  • argvus-session — infraestrutura de ciclo de vida de sessão, ambiente e supervisão de processos do ARGVUS;
  • argvus-appearance — recursos de aparência compartilhados, como wallpapers e fontes;
  • argvus-storage — integração de armazenamento removível;
  • argvus-calendar — integração nativa de calendário;
  • argvus-default-apps — gerenciamento de aplicações padrão;
  • argvus-accounts — metadados de conta local e integração de avatares;
  • argvus-greeter — greeter de login GTK4 para o greetd;
  • argvus-waybar — integração e empacotamento Waybar do ARGVUS;
  • argvus-splash — experiência de boot Plymouth do ARGVUS;
  • argvus-extras — pacotes adicionais selecionados usados pelo ambiente.

O ARGVUS também integra projetos upstream, como:

  • Hyprland;
  • Waybar;
  • Rofi;
  • Wofi;
  • Quickshell;
  • emuladores de terminal, gerenciadores de arquivos e outras aplicações de propósito geral.

Um componente upstream integrado não se torna software desenvolvido pelo ARGVUS.

O ARGVUS preserva essa distinção em sua documentação e atribuição.

O que o ARGVUS detém é o ambiente de desktop no qual esses componentes são selecionados, configurados, iniciados, supervisionados e integrados.

Foco do projeto

Seção intitulada “Foco do projeto”

O ARGVUS é intencionalmente focado como um ambiente de desktop para Arch Linux.

O projeto não precisa se tornar uma distribuição Linux para fornecer uma experiência de instalação completa no Arch, e não precisa criar substitutos para cada aplicação de desktop para se qualificar como ambiente de desktop.

Sua prioridade de desenvolvimento é a camada que diferencia a experiência ARGVUS:

As aplicações de propósito geral podem continuar vindo de projetos upstream, a menos que uma aplicação específica do ARGVUS tenha um motivo claro para existir.

Isso mantém o projeto gerenciável e dá a ele uma identidade clara.

Definição

Seção intitulada “Definição”

A descrição preferida do projeto é:

O ARGVUS é um ambiente de desktop completo baseado em Hyprland para Arch Linux.

Uma descrição mais arquitetural é:

O ARGVUS é um ambiente de desktop que detém e gerencia a sessão gráfica, usa o Hyprland como seu compositor Wayland, supervisiona seus componentes essenciais de desktop por meio do Gerenciador de Sessão ARGVUS, integra serviços nativos do ARGVUS e aplicações upstream selecionadas, e é empacotado nativamente para Arch Linux.

A primeira frase é adequada para páginas do projeto e descrições curtas.

A segunda explica a fronteira técnica com precisão.

Status de desenvolvimento

Seção intitulada “Status de desenvolvimento”

O ARGVUS está em desenvolvimento ativo.

O projeto fornece uma sessão de desktop Wayland distinta, uma camada dedicada de gerenciamento de sessão e um conjunto crescente de componentes ARGVUS coordenados.

A arquitetura é intencionalmente modular: o ARGVUS detém a sessão e a experiência de desktop enquanto continua a reutilizar software upstream maduro quando apropriado.

Esse modelo de desenvolvimento não torna o ARGVUS uma distribuição ou uma coleção de dotfiles.

O ARGVUS é desenvolvido como um ambiente de desktop.
