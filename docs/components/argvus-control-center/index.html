Control Center

The Control Center is ARGVUS’s keyboard-first settings application. Use it when you want to configure the desktop rather than perform a one-time action.

Control Center and Control Panel

Section titled “Control Center and Control Panel”
Use… For…
Control Center Themes, wallpapers, effects, layout, taskbar behavior, fonts, default applications, keyboard and input settings, language, region and system configuration.
Control Panel Current status and frequent actions such as volume, brightness, network, notifications, power and session controls.

The Control Panel can expose quick controls for a setting that is configured permanently in Control Center. For example, use the panel for a quick appearance or display action, and Control Center when you want to change the desktop configuration behind it. See Control Panel and Where to configure things.

Main areas

Section titled “Main areas”

The current Control Center home provides these areas:

The home is a catalog of destinations grouped in six cards. Each destination opens its page directly, and the search finds it under any card.

  • Appearance — customize the desktop: Desktop Style (theme, appearance mode, accent color, wallpapers, icons and fonts), Application Style (terminal and launcher transparency), Taskbar, Control Panel and Widget Telemetry.
  • Desktop & Input — configure the workspace: Hyprland (window rules, window spaces, animations, blur, borders, shadow and the installed version), Displays, Keyboard & Shortcuts and Mouse & Touchpad.
  • Preferences — personal and regional settings: Language & Region (the language, time zone, formats and keyboard layout hub), Date & Time, Default Applications, Power and Session.
  • Hardware & Connectivity — devices and connections: Hardware Overview, Network & Wi-Fi, Bluetooth, Audio and Storage.
  • System Administration — manage the operating system: Packages, Services, Boot, Hostname, Users & Groups, Firewall and Notifications (Do Not Disturb).
  • Settings — the Control Center itself, listed after the cards: Language (the user language) and Style (decorative icons and transparency). Press s to open it.
  • Tools & Diagnostics — developer and maintenance tools: ARGVUS Welcome, Projects, Snippets (text saved for argvus snippets, typed with SUPER + ALT + N), SSH keys (key pairs in ~/.ssh managed by argvus keys), GPG keys (the keyring managed by argvus gpg; gpg-agent uses pinentry-gtk), Dev Services, System Doctor and About ARGVUS.

ARGVUS Welcome

Section titled “ARGVUS Welcome”

Choose Open ARGVUS Welcome under Tools & Diagnostics, search for welcome, or run argvus welcome. Welcome is integrated into the Control Center and uses its single window. Enter opens the selected settings page; when finished, return to the guide with Esc. F6 Next checks off the current step and opens the next one in the same window. Esc only goes back, and Enter on the checklist always opens the selected page. O reviews the step again, S skips without checking it off, and F finishes the guide even with optional steps pending. Cancelling or returning does not complete a step. Existing progress is preserved.

The guide covers language and region, displays, hardware and drivers, network, audio, Bluetooth, appearance, power, default applications, and session startup. It never installs drivers or packages and does not apply system changes by itself. Progress is stored in $XDG_STATE_HOME/argvus/welcome/progress.json (or ~/.local/state/argvus/welcome/progress.json).

After the desktop is ready, the session runs argvus welcome --if-needed for TTY, ARGVUS Greeter and other login managers. It opens Welcome unless per-user progress records opened, completion or dismissal. The first successful render saves opened in ${XDG_STATE_HOME:-$HOME/.local/state}/argvus/welcome/progress.json, preventing reopening on later logins. It does not depend on /etc/skel. Existing accounts without that record also receive one automatic opening. Failures before rendering allow another attempt at the next login. Manual argvus welcome remains available.

The exact provider pages can depend on installed packages and permissions. Do not assume that a missing optional domain is a broken Control Center.

When the grid has more entries than fit on screen, a scrollbar appears along the right edge to show there is more below.

Finding a setting

Section titled “Finding a setting”

The home screen registers settings by title, category, identifier and keywords. Search is accent-insensitive and accepts practical terms such as theme, wallpaper, shortcut, mouse, monitor, network, user and DPI. Exact title matches are ranked first, followed by a title prefix, any word of the title or category that contains the typed text, and finally keyword matches — so typing any part of a word (not only its start) can still find the destination.

The visible menu is capability-aware. A route can be absent when its provider is not installed, when the hardware is not available, or when the current session cannot provide the required capability. Search is therefore also a useful way to discover what this installation can configure.

The main settings tree currently includes:

Area Current destinations
Appearance Desktop Style: theme, appearance mode, accent color, wallpapers, icons and fonts; Application Style: terminal and launcher transparency; Taskbar; Control Panel; Widget Telemetry
Desktop & Input Hyprland (window rules, window spaces, animations, blur, borders and shadow), Displays, Keyboard & Shortcuts, Mouse & Touchpad
Preferences Language & Region (language, time zone, formats, system locales and keyboard layout), Date & Time, Default Applications, Power, Session
Hardware & Connectivity Hardware Overview (summary, CPU, GPU, memory, devices), Network & Wi-Fi, Bluetooth, Audio, Storage
System Administration Packages, Services, Boot, Hostname, Users & Groups, Firewall, Notifications
Settings Language (user language), Style (icons and transparency)
Tools & Diagnostics Projects, Snippets, SSH keys, GPG keys, Dev Services, System Doctor, About ARGVUS

Some of these are full pages and some are subpages reached through search or a domain summary. The exact list is determined by the installed ARGVUS providers.

Each page shows its path in the header, for example Control Center > Hardware & Connectivity > Audio. The path starts with the Home card that lists the page, so the same page reads the same from the Home, from search and from the CLI. The root and the card names are translated: the Portuguese interface shows Central de Controle > Hardware e conectividade > Áudio.

What each area is for

Section titled “What each area is for”

Appearance

Section titled “Appearance”

Appearance is the main customization area. Its Desktop group holds the theme (with its Sticky or Float mode), the appearance mode, the accent color, the wallpapers, the icon theme and the Fonts page, and its Application Style group holds the terminal and launcher transparency. Taskbar, Control Panel and Widget Telemetry are listed directly under Appearance on the home and reuse Appearance’s shared transparency page for their own surfaces. Blur is one global setting, under Hyprland > Blur, and it applies to every ARGVUS surface that has blur enabled. That page edits its Enable switch and the Hyprland blur values (Size, Passes, Brightness, Noise, Contrast, Vibrancy and Vibrancy darkness) as a draft, and nothing changes until Apply is selected. Animations works the same way under Hyprland > Animations: its Enable switch, the Custom curves (Bézier, Spring, Linear and Ease-out) and the five animation categories form one draft that is applied together with Apply. Bézier and Spring have editable parameters (the Bézier points and the spring mass, stiffness and dampening); Linear and Ease-out are fixed curves, so their page only lists their control points and cannot be edited. The style choices follow what Hyprland 0.56.2 draws: Opening and Closing offer slide, popin and gnomed, layer entrance and exit offer slide, popin and fade, and the workspace leaves offer slide, fade, slidefade, slidevert and slidefadevert. These controls coordinate with the appearance and session components instead of changing only the Control Center window.

Taskbar

Section titled “Taskbar”

Taskbar configures the panel’s position, the spacing around it and its windows, its height and border, the utility icon group, and the date/time blocks, plus its own transparency. It is listed under Appearance on the home. In Sticky mode, Spaces > Bottom defaults to 2; Float keeps its 18-pixel baseline.

Height chooses 24, 28 (the default), 32 or 36 pixels. Border has an Enable switch and a Thickness of 1 to 3 pixels, with 1 as the default. With the border off, the taskbar window, the right group and the MPRIS player have no border. These changes are a draft until Apply is selected. The applied height and border are kept when the theme changes; until they are applied, the theme decides them.

The Icons page opens Optional modules, Workspace presentation, Launcher and Utilities. Optional modules can be shown or hidden individually: audio player, Focus, launcher, network, power profile, keyboard layout, memory, CPU and temperature readings, date, clock, battery, system tray, notifications, removable devices, recording, Bluetooth, audio input/output and keep-awake. Workspaces remain available and can show their names (the default) or application icons. The focused-window title, Settings and Power actions are always available. Launcher visibility is controlled in Optional modules; its submenu changes the custom icon. Changes take effect after Apply, which restarts the taskbar.

Control Panel

Section titled “Control Panel”

Control Panel configures the visibility and order of its quick-action cards, plus its own sessions and transparency.

The page opens and accepts input as soon as the card settings are read. The cards that depend on hardware (Bluetooth and Brightness) are checked in the background: until that check finishes they keep the availability last seen in this window, and the list updates on its own when the result arrives.

Widget Telemetry

Section titled “Widget Telemetry”

Widget Telemetry configures the system-information widget’s sessions and transparency.

Fonts

Section titled “Fonts”

Fonts is reached from Appearance > Desktop Style > Fonts. It lets you select a family and size for the taskbar, telemetry/system information, Control Panel, ARGVUS system interface, applications, terminal and browser. It also exposes font rendering settings such as antialiasing, hinting, subpixel mode and DPI. The default primary family is IBM Plex Mono; individual targets can be changed independently and restored from the Fonts page.

Default applications

Section titled “Default applications”

Default applications selects installed programs for roles such as terminal, file manager, text editor, terminal editor, browser, image viewer, PDF viewer, video player, audio player, archive tool and launcher. The selection is saved by ARGVUS and may update standard XDG associations.

Snippets

Section titled “Snippets”

Snippets is the page for the text that argvus snippets types with SUPER + ALT + N. It is in Tools & Diagnostics → Snippets (search snippets or run argvus control-center snippets).

  • New snippet — type a Name and a Content, then Save snippet. A name that already exists replaces that snippet’s content.
  • Saved snippets — listed with their position (1 email) and the content on one line. Enter on the content edits it. Type types the snippet, and Remove asks for confirmation.
  • Open picker — opens the same picker as SUPER + ALT + N.

Typing starts 3 seconds after you press Enter, because the Control Center itself has the focus at that moment. Click the field that should receive the text within that time. The page only edits one-line content; a multi-line snippet can be created in a terminal with argvus snippets add.

The page reads the entries from argvus-config and writes them through argvus snippets, so the launcher keeps the validation. When argvus snippets is not installed, the page says so.

SSH keys

Section titled “SSH keys”

SSH keys is the page for the key pairs that argvus keys manages. It is in Tools & Diagnostics → SSH keys (search ssh keys or run argvus control-center ssh-keys).

The page has four parts, from top to bottom:

How to use it

Section titled “How to use it”
  1. Open Control Center → Tools & Diagnostics → SSH keys. From the Home, you can also search for ssh keys.
  2. Find a key: press /, then type to show only the pairs whose name or comment matches. Enter ends the search and runs the highlighted row, as in the other lists, so check the row before pressing it; Esc clears the search.
  3. Create a pair: in Generate, select Name, press Enter, type the name and press Enter again. Select Type and press Enter to switch between ed25519 and rsa. Select Generate key pair and press Enter. The new pair appears under Keys at once, without a passphrase.
  4. Copy the public key: in the pair’s block, select Copy public key and press Enter. The contents of the .pub file go to the Wayland clipboard, ready to paste into a server’s authorized_keys or a Git host. The private key is never copied. This needs wl-clipboard (wl-copy); without it, the page says the key was not copied.
  5. Load a pair into the agent: in the pair’s block, select Load into agent and press Enter. A key without a passphrase is loaded at once, with no window. A key with a passphrase opens an ARGVUS terminal, where OpenSSH asks for it; close the terminal with Enter when it says the key is loaded. The page checks the agent every few seconds while it is open, so the row changes to Unload from agent by itself. To update at once, use Refresh in Actions.
  6. Remove a key from the agent: in the pair’s block, select Unload from agent. To remove every key, use Unload all keys from agent in Actions. The key files stay on disk.
  7. Delete a pair: in the pair’s block, select Delete and press Enter. The confirmation focuses Cancel, so a stray Enter does nothing. Press y to confirm, or n/Esc to cancel. A key that is loaded in the agent cannot be deleted; unload it first.

Moving around: ↑/↓ or j/k move through the list, Enter activates a row, Esc goes back and ? shows help. Tab moves the focus into Actions, where ←/→ choose a button and Enter runs it. ↑/↓ bring the focus back to the list.

Passphrases are never typed into the Control Center and never passed as command arguments. The page reads the list with argvus keys list and writes only through argvus keys. When argvus-keys is not installed, the page says so.

Troubleshooting

Section titled “Troubleshooting”
Symptom Cause and fix
Could not open a connection to your authentication agent after Load into agent The terminal did not receive the agent socket. Hyprland keeps the environment it started with, and the agent may have started later. Update argvus-launcher, which falls back to $XDG_RUNTIME_DIR/ssh-agent.socket, and check systemctl --user status argvus-ssh-agent.service.
Agent shows Agent unavailable The launcher cannot reach the agent. Check the service as above.
The page says argvus-keys is not installed Update the argvus package: argvus keys is a subcommand of it.
Delete shows an error The key is loaded in the agent, and it is kept. Unload it first, then delete it again.

GPG keys

Section titled “GPG keys”

GPG keys is the page for the keyring that argvus gpg manages. It is in Tools & Diagnostics → GPG keys (search gpg keys or run argvus control-center gpg-keys).

The page has these sections, from top to bottom:

▾ marks an expanded section and ▸ a collapsed one. Enter or Space expands or collapses it.

How to use it

Section titled “How to use it”
  1. Open Control Center → Tools & Diagnostics → GPG keys. From the Home, you can also search for gpg keys.
  2. Pinentry is fixed to pinentry-gtk. The page only shows it. The first time a key is generated, ARGVUS writes that pinentry into gpg-agent.conf, between its own marker lines, and keeps your other lines. If you already wrote a pinentry-program line outside those markers, generation stops with an error so that you can remove that line.
  3. Create a key: in Generate key ▾, type Full name and E-mail. Both are required, and Generate key stays disabled until both have text. Comment is optional. The user ID becomes Name (comment) <e-mail>.
    • Algorithm switches between RSA and DSA ElGamal. A DSA key gets an ElGamal encryption subkey; an RSA key gets an RSA one.
    • Key strength cycles through the sizes of the algorithm: RSA 1024, 2048 and 4096; DSA 1024, 2048 and 3072. gpg does not create DSA keys above 3072 bits, so 4096 is not offered for DSA.
    • Expiration date opens its own page. Type the date in the layout of your language: DD/MM/YYYY in pt-BR, YYYY/MM/DD in English. The date must be after today. Turn on Never expires to make the key permanent; the date field is then disabled and not used.
    • Passphrase opens its own page. Protect with a passphrase is on by default; type the Passphrase and then Confirm passphrase. The two must match. Turning protection off clears both fields, and the page asks for confirmation before it generates an unprotected key.
  4. Select Generate key and press Enter. The key gets a signing key and an encryption subkey. The passphrase is sent to the launcher on its standard input, never as a command argument. If generation fails, the other fields stay, but the passphrases are cleared and must be typed again.
  5. Cancel clears every field of the form and returns the dates and sizes to their defaults.
  6. Import: in Import ▾, choose Import public key… or Import private key…. The file manager opens so that you can choose the file. A private key asks for confirmation first, and its passphrase is asked by gpg when the key is used. If the file manager is a graphical one, it cannot report the file to the page; the page then opens a field where you type the path.
  7. Keys › opens the keyring. Each key shows its identity, fingerprint, type, expiry and whether its private key is in the keyring. Each key has these actions:
    • Edit key › opens the key’s own page (described below).
    • Export public key… asks for a file path, proposed as ~/<fingerprint>.asc. The file is created with mode 600. An existing file is never replaced.
    • Export private key… appears only for keys with a private part. It asks for confirmation, then for a file path, proposed as ~/<fingerprint>-private.asc. The file is created with mode 600.
    • Copy public key and Copy fingerprint copy to the Wayland clipboard with wl-copy.
    • Delete key… asks for confirmation, with the focus on Cancel. It removes the key and its private part.
  8. Find a key: on the Keys page, the search bar at the top filters the keys. Type to narrow the list; the search matches the identity (which includes the comment) and the fingerprint. Esc clears the search.
  9. Edit key › shows the key’s details, then these actions:
    • Expiration date › changes the expiry of the key and of each of its subkeys. Use Never expires to remove the expiry. Apply saves the change.
    • Change passphrase asks the old and the new passphrase in the pinentry window.
    • Sign key with › certifies this key with one of your other keys that has a private part. The signer’s passphrase is asked. The page asks for confirmation first.
    • Revoke key › lists the reasons: no reason, key compromised, key superseded, key no longer used. Each one asks for confirmation. A revoked key cannot be used any more.
    • Trust sets how far you trust the key: not set, marginal, full or ultimate.
    • Publish to keyserver… sends the public key to the keyserver set in gpg.conf, after confirmation. Fetch from keyserver downloads the key from that keyserver.

Moving around: ↑/↓ or j/k move through the list, Enter activates a row, Esc goes back and ? shows help.

Passphrases are typed only into the masked fields of the passphrase page, or into the pinentry window. The page sends the generation passphrase to argvus gpg on standard input, and the launcher hands it to gpg on a file descriptor, so it never appears in the process list, in a command argument or in the logs. Key changes run in the background; while one runs, the others wait. The page reads the keyring with argvus gpg list and writes only through argvus gpg. When argvus gpg is not installed, the page says so.

Not in the page yet: searching the keyserver for a key by name or e-mail. Use Fetch from keyserver with a known fingerprint.

Troubleshooting

Section titled “Troubleshooting”
Symptom Cause and fix
The page says argvus gpg is not available The installed argvus-launcher predates the GPG command. Run argvus gpg list in a terminal: unknown command means the package must be rebuilt and installed. Keys also need gnupg.
Generate key stays disabled Type both Full name and E-mail.
A status line says argvus-gpg: pinentry-gtk is not installed Install the pinentry package, which provides pinentry-gtk.
Generation stops with a pinentry-program error gpg-agent.conf sets a pinentry outside the ARGVUS block. Remove that line; ARGVUS then writes its own.
Pinentry shows Not set gpg-agent uses its built-in default until the first key is generated from the page.
The page says the installed argvus-launcher is older than the Control Center Reinstall argvus-launcher: run make build and then make install in its repository, and reopen the page. The key actions stay off until the versions match.
The file manager opens, but the page asks for a path The file manager is a graphical one and cannot report the chosen file. Type the path in the field.
Copy public key says it could not copy wl-copy is not installed or the Wayland session is not available. Install wl-clipboard.
Edit key › says the key is no longer in the keyring The keyring changed since the page opened. Go back to Keys › and refresh.
A status line shows argvus-gpg: ... The launcher refused the action, and the text gives the reason, such as an invalid expiry, a file that already exists, or a missing --yes.
An action waits and nothing happens The pinentry window is hidden or was not opened. Check the session exposes WAYLAND_DISPLAY or DISPLAY.
The import is refused The file contains no key of the kind chosen. Public keys go through Import public key…; private keys through Import private key….

Language & Region

Section titled “Language & Region”

This card lists Language (the regional locale), Time Zone, Date & Time, System Locales and Keyboard Layout, and each one opens directly from the home. The keyboard pages also hold the variant and console keymap. The home search also exposes keyboard shortcuts and mouse/touchpad settings as direct settings routes.

Both Preferences > Language & Region > Language and Settings > Language save the same user preference: LANG in $XDG_CONFIG_HOME/locale.conf (default ~/.config/locale.conf), for example LANG=en_US.UTF-8. Comments and regional variables are preserved. No global file or parallel ARGVUS language setting is written. An unconfigured user gets English; legacy session.language and data/language files are ignored. Log out and back in to apply the language to the full session and applications.

System Locales changes /etc/locale.gen and runs locale-gen, so applying it requires administrator authorization. A persistent [WARN] notice above the footer identifies pages with administrative settings. The same notice covers time zone, date/time, hostname, console keymap, account and group editing, firewall, system services, CPU governor, power profiles and policies, boot configuration, package operations, snapshots and protected network changes. Personal preferences, user services and read-only pages do not receive this notice. The notice is informational; authorization is requested only when an action needs it.

Hardware and displays

Section titled “Hardware and displays”

When the corresponding capabilities are installed, the Control Center can show hardware information such as CPU, GPU, memory, power and devices. The input page configures mouse and touchpad behavior; the display area handles monitor resolution, refresh rate, scale, position, orientation, primary display, VRR and HDR where supported by the running session. Display changes apply immediately. After a change that can leave the screen unusable (resolution or refresh rate, position, mirroring, disabling a monitor, color depth) or after Apply, Control Center asks whether to keep it, with the focus on Revert: press y to keep it; n, Esc or Enter revert it, and without an answer within 15 seconds the previous configuration comes back automatically. Removing the saved configuration of a disconnected monitor and deleting a profile ask for confirmation; profiles open their own page with Apply profile, Rename and Delete profile. The layout is saved through argvus config monitor-set, monitor-primary, monitor-workspaces and monitor-remove, so the canonical /displays section of config.json is the only source of the monitor layout. Only the profile catalog stays in display/config.toml.

Connectivity and audio

Section titled “Connectivity and audio”

The network area exposes the installed network provider’s status and connection pages, including Wi-Fi, Ethernet, VPN, DNS and proxy routes when available. The firewall is listed under System Administration. Bluetooth is conditional on Bluetooth support. The audio area is provided when its optional capability is enabled and integrates with the installed audio service.

The Network & Wi-Fi home and its Status page fill in as each NetworkManager query answers, instead of after the slowest one: the device list first, then the radio, the connected interfaces’ addresses and DNS, the saved connections and the Wi-Fi networks NetworkManager already knows (a new scan only runs from the Wi-Fi page with r). Until the device list arrives the rows say Loading…, and the Wi-Fi switch is only offered when the computer has a Wi-Fi card. Starting an action (the Wi-Fi switch, connecting, DNS) while a page is refreshing replaces the refresh, and the page refreshes again when the action ends.

Connections, inspired by nmtui

Section titled “Connections, inspired by nmtui”

Network & Wi-Fi > Connections lists every NetworkManager connection profile, grouped by type, with the device it is active on (★ Active · eno1), whether it is a port of a bridge, bond or team, and whether it is read-only. Enter opens the profile in the editor, a connects or disconnects it, / filters by name and r refreshes. Activate a connection is the same list where Enter brings a profile up or down, as in nmtui. The detail pages of an interface, a saved Wi-Fi network and a VPN have an Edit connection row that opens their profile.

Add connection creates Ethernet, Wi-Fi, Hotspot, DSL (PPPoE), Bridge, Bond, Team, VLAN, IP tunnel, Loopback and WireGuard profiles, and one VPN profile per installed NetworkManager VPN plugin (OpenVPN has its own form; other plugins edit their settings as key=value entries). It also imports a WireGuard .conf or a plugin file such as an .ovpn (nmcli connection import). Team needs the libteam package, DSL needs ppp and a VPN needs its plugin (for example networkmanager-openvpn); without them the row is disabled and says what to install. WEP, InfiniBand, MACsec and Open vSwitch are not offered.

The editor is one list of foldable sections: General (name, interface, connect automatically, priority, available to all users, metered), the type’s own settings, IPv4 and IPv6 (method, addresses, gateway, DNS servers, search domains, routes, ignore automatic DNS or routes, never use as the default route, route metric, privacy extensions, address generation). Choices and numbers change with ←/→; Enter types a value; lists (addresses, DNS, routes, allowed IPs) open their own page, where Enter edits an entry, clearing it removes it and Add entry appends one. Fields that do not apply to the chosen method are shown disabled. A bridge, bond or team picks its Ethernet Ports on a sub-page; WireGuard edits its Peers on a sub-page and can Generate key pair (with wg, from wireguard-tools, a dependency of the argvus package); the public key of the private key is shown below it.

Nothing reaches NetworkManager until Save, which stays disabled while nothing changed or while a field is invalid, and then says which field and why. Only the settings that changed are written. Saving a connection that is active asks first and then reconnects it, so the new settings apply at once (this can briefly interrupt the network). Esc with unsaved changes asks before discarding them. Delete connection, in the Danger zone, asks for confirmation with the focus on Cancel; deleting a bridge, bond or team also deletes its ports.

Passwords, private keys and preshared keys are never read back: their rows say Unchanged until a new value is typed, and the new value is shown masked. They are written through the standard input of nmcli connection edit, never as command arguments. Changes run as the session user: local members of wheel are allowed by NetworkManager’s polkit rule, and other users are asked for the administrator password by the session’s polkit agent.

Power and session

Section titled “Power and session”

Power provides the system power controls and policy pages available to the installation, including the Keep Awake toggle. When enabled, Keep Awake prevents the ARGVUS idle policy from starting automatic screen-lock and display-power timers. Session exposes ARGVUS session status, components, autostart, diagnostics and logs. On Power, the Actions bar under the list holds Suspend, Hibernate and Refresh (r refreshes too): Tab or ←/→ move to it, Enter runs the focused button, ↑/↓ bring the focus back to the list, and Esc goes back. Suspend and Hibernate ask for confirmation first. These pages may require system permissions and should be distinguished from the quick actions in the Control Panel.

System tools

Section titled “System tools”

The system section can expose boot information, packages, services, storage, diagnostics, user/group administration and system information. These are administrative or diagnostic tools; a page may be read-only or require authorization depending on the operation.

Services has four pages: system units, user units, failed units and the journal (Logs). Each unit list shows a Filter: line, which f cycles, and a bordered Search: box, opened with /. Each unit shows its Active and Enabled state as filled or empty dots. In Logs, b switches between the current and the previous boot, u cycles the unit and p cycles the priority; the Filter: line shows the values in use. Enter opens a unit or a log entry.

Dev Services reports three development-facing sources in one read-only page: the current user’s systemd services, the TCP ports currently listening (ss), and the running containers from any installed container runtime (Podman, Docker). It only appears on the Home grid when at least one of these is available on the system — a machine with no systemd user session, no Podman and no Docker does not show the entry. r refreshes the three sources independently, so a slow or failing one (for example a container runtime that stopped responding) does not block the others from showing their data.

Packages is grouped by source. Official Repositories and, when an AUR helper (paru or yay) is installed, AUR (Arch User Repository) each open Install, Remove and Update; Cache, History, Downgrade and Mirrors follow. The three tasks share one screen: the Search box fixed at the top takes the letters you type, and the packages are listed under it in the Results block (Updates on Update), where an empty list says why (for example No results, No matching items or No pending updates). Install searches the repositories (pacman -Ss) or the AUR when you press Enter or type a search with /; Remove lists the installed packages (the AUR list shows the packages built outside the repositories, pacman -Qm, and while the AUR menu is shown they leave the Official list); Update lists the pending updates (pacman -Qu, or paru -Qua/yay -Qua for the AUR). On a package, Enter runs the task of the screen and → opens the package page, with Install (or Reinstall) and, in its Danger zone, Remove; ← or Esc go back. Official Repositories → Remove starts with Orphans, where Space marks packages ([x]), Enter opens one and Remove marked removes them together. On Update, Tab moves to the Actions bar under the list (Upgrade all and Refresh database, or Upgrade all (AUR) on the AUR), ←/→ move between its buttons, Enter runs the focused one and ↑/↓ (or typing) bring the focus back to the list; Upgrade all is dimmed and skipped while no update is listed. The breadcrumb and the global search follow the same path, for example Packages > Official Repositories > Remove > Orphans. The cache cleanups are in the Danger zone of the Cache page, and Mirrors → Configure mirrors sets the reflector options before Generate preview. Every package operation shows its plan, or for the AUR the PKGBUILD warning, and asks for confirmation (y confirms, n or Esc cancels) before it runs, and its output is shown while it runs. AUR operations run the helper as your user (-S <package> to install or update one, -Sua to update all); AUR removals use the same pacman -Rns as the official packages. When other installed packages depend on the package you remove (official or AUR), the confirmation names them and offers two ways: Remove only the selected package (pacman -Rdd, which skips the dependency checks, so the packages that need it may stop working) or Remove with dependents (pacman -Rcns, with the number of packages it removes). The focus starts on Cancel, which keeps every package; Enter runs the focused row and there is no y shortcut in this choice.

Official Repositories → Repositories adds and manages unofficial pacman repositories. Add is a draft: choose the Source of the configuration (URL of a .conf file, Text typed or pasted in a multi-line editor, or Form with Name, Server and SigLevel, written in the Arch Wiki layout) and, under Signing key, a Key from a URL or Text (or None). Choices move with ←/→ or Enter; text fields open an editor where Enter saves a single line, Ctrl+S saves several lines, pasting works and Esc cancels. Downloads accept only https:// addresses. Review and add downloads and checks everything as your user and then asks for confirmation, listing the repositories, servers and SigLevel and the key’s user ID and fingerprint in groups of four, to compare with the one the repository publishes. Confirming imports the key and signs it locally (pacman-key --add, --lsign-key), writes /etc/pacman.d/<name>.conf (named after its first section) and adds Include = /etc/pacman.d/<name>.conf to /etc/pacman.conf (an existing commented line for the same file is enabled instead). Afterwards the Control Center offers pacman -Syu, so the new databases are synchronized without a partial upgrade. Leaving Add with a draft asks before discarding it. List shows every unofficial repository, written in pacman.conf itself or included from /etc/pacman.d/, enabled or disabled; official sections are never listed. A repository page shows its file, SigLevel, servers and recorded key, an Enabled toggle and, in the Danger zone, Remove. Disabling comments the Include line, or prefixes each line of an inline section with #argvus-off ; removing deletes the line or the section and the included file. Repositories of the same included file are enabled, disabled and removed together. When the Control Center imported the key, Remove also offers removing it from pacman’s keyring (pacman-key --delete). Every change to /etc/pacman.conf keeps a backup next to it (pacman.conf.argvus-backup-…), and installed packages are never removed.

Users and groups

Section titled “Users and groups”

When the account provider is available, open Control Center → System Administration → Users & Groups → Users or search for users. The interface can list normal and system accounts, create a user, edit account metadata, manage supplementary and primary groups, change or lock a password, unlock it, require a password change at the next login, set or remove an avatar, and enable automatic login.

User creation asks for a username, full name, shell, supplementary groups and an optional password confirmation. A blank password creates the account with its password locked; it does not silently create a usable password. A user page groups the account fields (full name, shell, primary and supplementary groups, followed by Save changes), the Automatic login toggle, the Password actions (change, lock, unlock, require a change at the next login) and the Avatar actions. Username, UID / GID and home directory are shown for information only. The Danger zone at the end holds the separate destructive actions to delete the account while keeping its home directory or to delete the home directory as well. Read the confirmation text carefully before choosing the latter. Account operations are privileged and may open the system authorization prompt. Avatars can be consumed by the greeter through the account’s standard face image integration.

Automatic login starts the selected account’s session at the next boot without showing the login screen, the same convention GNOME, LightDM and SDDM use for this feature: no password is stored anywhere. Enabling it for one account disables it for any previously configured one (only one account can auto-login at a time). It applies once, at the next boot; after a manual logout the normal login screen returns for the rest of that session. The toggle is applied immediately, with a confirmation prompt, and is only available to administrators.

Groups have their own list and edit pages, including member management and group deletion. The Control Center does not replace the system’s account policy: protected system accounts and operations requiring authorization remain subject to the operating system’s restrictions.

Control Center settings

Section titled “Control Center settings”

Settings is the last entry of the home. Its Language page sets the user language through locale.conf, and its Style page controls the decorative icons and the Control Center transparency. Style does not hold blur: blur is a global Hyprland setting, under Hyprland > Blur. The Style page changes the settings application’s presentation; it is not a switch that disables ARGVUS services or removes settings providers. About ARGVUS

Section titled “About ARGVUS”

About ARGVUS is in Tools & Diagnostics → About ARGVUS (search about, hardware or firmware, or run argvus control-center about). It has five tabs, switched with Tab/Shift+Tab, ←/→ or h/l: System & Hardware, About, Donate, Credits and Copyright. The header shows the full path, for example Control Center > Tools & Diagnostics > About ARGVUS > System & Hardware.

System & Hardware is read-only and groups the facts of this machine in three sections, with the values aligned in one column:

Section Fields
Boot Firmware (vendor, version and date), Type (UEFI or Legacy (BIOS)), Secure Boot (UEFI only), Virtualization, Bootloader
System ARGVUS, Hostname, Operating system, Distributor, Kernel, Architecture, Window manager (Hyprland), Compositor (Wayland), GPU driver, GTK, Theme (with Dark or Light), Displays (one line per monitor), Audio (PipeWire), Shell (Quickshell), Login (greetd), Init (systemd), Packages, Uptime, Locale
Hardware Battery (one line per battery), CPU (with its maximum frequency), Threads, Cores, GPU, Memory (used / total), Swap, Storage, Model (only when it differs from the motherboard), Motherboard

Every value is read from the running system, without privileges, and the page works the same on any machine. A value that cannot be read is shown as N/A, and a line that does not apply is left out:

  • Firmware, Model and Motherboard come from DMI (/sys/class/dmi/id); placeholder values such as To be filled by O.E.M. are ignored. Type and Secure Boot come from /sys/firmware/efi, and Virtualization from systemd-detect-virt.
  • Bootloader is read from the LoaderInfo EFI variable, which systemd-boot, Limine and other bootloaders that follow the Boot Loader Interface publish. GRUB does not publish it, so it is recognized by /boot/grub (or /efi/grub) and shown with the version of the grub package.
  • The versions of ARGVUS, Wayland, Mesa, PipeWire, Quickshell, greetd, systemd and GRUB come from one pacman -Q query and are shown without the epoch and package release (1:25.2.3-1 becomes 25.2.3). The Hyprland version comes from hyprctl version, or from the package when no session answers.
  • GPU driver names the driver bound to each DRM card in /sys/class/drm. A proprietary driver shows its module version (for example nvidia 580.82.07); an in-kernel driver shows the Mesa version (for example amdgpu (Mesa 25.2.3)).
  • Displays lists the active monitors from hyprctl monitors -j: connector, resolution, refresh rate and scale (the scale is left out at 1).
  • Packages counts all installed packages, the explicitly installed ones and the foreign ones (AUR or built locally), from pacman -Qq, -Qqe and -Qqm.
  • Uptime comes from /proc/uptime and is the value when the page was opened. Locale comes from LANG in /etc/locale.conf.
  • Battery lists the batteries of the computer from /sys/class/power_supply, selected by type, so peripherals such as wireless mice are not counted. Each line shows the charge, the state, the health (full capacity compared with the design capacity) and the charge cycles when the firmware reports them. A machine without a battery shows Not detected.
  • CPU adds the highest maximum frequency among all cores (cpufreq), which is the rated maximum on hybrid processors; it is left out where cpufreq is not available, as in most virtual machines. Threads and Cores come from /proc/cpuinfo.
  • Memory and Swap come from /proc/meminfo (zram included); a system without swap shows Disabled.
  • Storage describes the disk under /: its model, its kind (NVMe, SSD, HDD or eMMC/SD; virtual disks show no kind), the file system and the used and total space. The disk is found through partitions, LUKS and LVM down to the physical device.

The values are read in the background the first time the page is drawn, so neither the Control Center start nor the page opening waits for them; the tab shows Loading system information… meanwhile. Press c on this tab to copy the whole report as plain text to the clipboard (with wl-copy), for example to paste it in a bug report.

Keyboard use

Section titled “Keyboard use”

The settings application supports keyboard navigation. Every page is a single list: use the arrow keys or j/k to move, Enter to open or run the selected row, Space to toggle, Esc to go back, / to search lists and ? for help; the footer shows the keys that apply to the selected row. Actions are rows of the list, not buttons, and Tab does not move to them, except on the pages with an Actions bar under the list (Default Apps, Time Zone, Keyboard Layout, System Locales and SSH Keys). Rows that only show information are skipped. While a text field, a search or a list filter is active, q and ? are typed as text instead of quitting or opening the help. On Default Apps, Restore Defaults is the button in the Actions bar under the list: Tab or ←/→ focus it and Enter asks for the reset. Reset defaults on the other pages and Restore all shortcuts are rows in a Danger zone at the end of their pages; r asks for the same reset, and on the shortcuts list r restores the selected shortcut after a confirmation. On Language & Region → Keyboard Layout, / focuses the Search box at the top of the page, and Esc clears it; The ● marks the layout in use. It follows the taskbar and the keyboard shortcut that cycle layouts, and the page updates within about a second without writing anything to the configuration. These keys only change a draft, and the Apply button in the Actions bar under the list writes the layouts and the default to Hyprland in one step. Leaving with a zone that was not applied asks for confirmation first. In Appearance, every page is a single list: the footer shows only the keys that apply to the selected row, and Space also opens or selects the row. Persistence and reset

Section titled “Persistence and reset”

Settings pages apply changes through their owning provider and save the supported user state. Appearance changes are stored in the canonical configuration, and argvus-config is the only component that writes the derived consumer files under ~/.config/argvus/data/generated/; those generated files are not the place to make a permanent edit. Input and keybinding pages have their own persisted state and reset actions. Other system changes may require permissions or a service reload.

There is no global reset for every ARGVUS setting. Restore a change from the page that owns it, or use the relevant feature’s documented recovery procedure.

Reset support is deliberately per domain:

  • Appearance provides a reset for the highlight color to the active theme default. It does not provide a single global appearance reset; restore other appearance values from their own controls.

  • Fonts can restore all font settings, a target, or an individual setting.

  • Default applications can restore all defaults, a category, or an individual selector.

  • Keyboard shortcuts can restore one binding or all bindings and then reload the generated session bindings.

  • Window rules is in Desktop & Input → Hyprland → Window Rules (search window rules or run argvus control-center window-rules). Each rule has a Workspace row (Enter or ←/→ steps through 1 to 10) and a Window classes row that opens a text field with comma-separated regular expressions. Add rule creates rule-N with workspace 1 and no classes. Each rule’s Remove rule sits in the Danger zone and asks for confirmation. Every change is written to hyprland.window_rules in argvus config and reloads the configuration immediately; invalid class patterns are rejected and shown as an error.

  • Projects is in Tools & Diagnostics → Projects (search projects or run argvus control-center projects). Add project folder and Add root folder sit at the top of the page and open a text field with the path; the launcher checks that it is a directory and shows the error otherwise, including when the folder would push the effective project count past 9 (SUPER + ALT + 1..9 cannot address more). Each configured folder, marked as a root (its subfolders are projects) or a single project, gets its own block below the form with a Remove row that asks for confirmation. The page calls argvus-projects, so changes are written by the launcher and apply the next time SUPER + O or SUPER + ALT + 1..9 runs. If argvus-projects is not installed, the page says so.

  • Other system pages expose reset, apply, delete or restore actions only when the underlying provider supports them.

Removing a user preference can make a provider fall back to its packaged/default state, but deleting files by hand is not a general recovery procedure. Prefer the page’s reset action or the documented feature-specific command.

System Doctor

Section titled “System Doctor”

Open Tools & Diagnostics → System Doctor, search for it, or run argvus control-center system-doctor. The previous diagnostics and diagnostic routes and category selectors remain available. Press r to refresh, Enter to inspect a check, o in a detail to open its related page, and Esc to go back. Collection runs in the background and is read-only.

Checks use systemd failed-unit counts, graphics tools and the Storage snapshot for filesystem usage and SMART health. A problem requires evidence; unavailable tools or inaccessible SMART data are shown as unavailable, and a failed or timed-out probe is an error. Categories without collected evidence do not imply a successful check. Package updates use the local pacman database and do not synchronize repositories; a lock file can be stale and does not prove an operation is running. Snapshot

Section titled “Snapshot”

Open Control Center > System Administration > Snapshot, search for Snapper, or run argvus control-center snapshot. The snapshot Cargo feature is included in full (the default), and is independent of storage.

This page manages only an existing Snapper configuration whose SUBVOLUME is / and whose FSTYPE is btrfs. It checks the mount containing / with findmnt; a configuration named root pointing elsewhere is not accepted. Multiple matching configurations require a selection. The snapper Arch package is optional and must be installed manually. Snapper must support --jsonout and explicit active/default columns. No configuration is created automatically.

On a non-Btrfs root the page displays This filesystem is not Btrfs and offers no snapshot operations. Detection failure, missing Snapper, missing root configuration, permission denial and backend errors are separate states. If normal-user queries are denied, press a — Authorize to request Polkit access. Administrative actions run in the restricted system-settings helper, not in an elevated TUI; authentication may be requested again on later queries. An existing graphical Polkit agent is required for authentication.

Keys: ↑/↓ select, Enter details/configuration, c create, d delete, p retention policies, r refresh, Esc back, ? help. On the retention view, ↑/↓ select a policy, e edit, c cycle cleanup algorithms and Enter open confirmation. Creation opens an optional description (up to 256 printable characters); an empty description uses “ARGVUS manual snapshot”. Both creation and deletion require confirmation, initially focused on Cancel. Deletion applies to one selected snapshot and rejects snapshot 0, the currently active snapshot and the default snapshot. The helper rechecks these conditions before invoking Snapper. Lists refresh after operations; an interrupted operation is never retried automatically. Inspect the refreshed list first.

To compare snapshots, select the base and press b, then select a different destination and press v. The page shows the ordered IDs, counts of created, removed and modified paths, and Snapper’s six status indicators. Select a path and press Enter to request its content diff; Esc returns to changed paths and then the snapshot list. The indicators encode creation/removal or content/type in position 1, permissions in 2, owner in 3, group in 4, extended attributes in 5, and ACL in 6. A dot means no change in that position. Status lists paths; diff shows textual content. Binary/non-UTF-8 diff output is not rendered. Diff output above 256 KiB is reported as truncated and not displayed. Ambiguous or malformed status lines are rejected. Snapper’s line format cannot represent paths with line breaks unambiguously; such names are unsupported. Permission errors can be retried through a — Authorize; a removed snapshot or changed root configuration requires refreshing the list. Backend tests use a fake ProcessRunner and do not require Snapper, Btrfs or root.

From the comparison, select a path and press r to review restoring the file from the destination snapshot. The helper verifies that both snapshots still belong to the root configuration, the path is still in the comparison, and the source is a regular file in Snapper’s standard /.snapshots/<id>/snapshot view. The bounded Snapper diff is shown when textual; binary or oversized diffs are identified without loading their full contents into the UI. Enter opens a separate confirmation naming the source and destination; Esc cancels without changing the file. Confirmation creates a single safety snapshot first, then uses Snapper undochange for only that path and checks that it matches the selected snapshot. The safety snapshot ID is reported and the snapshot is kept. Restoration shares the lock used by ARGVUS package upgrades, so it cannot overlap an official Control Center pacman transaction.

The first version accepts only root-owned regular files under root-owned parent directories that are not writable by group or others. It refuses directories, symlinks, hard links, special files, mountpoints/subvolumes, Snapper’s internal directory and user-writable locations. Files missing from the selected snapshot are never deleted. Snapper’s root undochange does not guarantee application or database consistency and is not atomic; the safety snapshot is a recovery point, not a guarantee. Snapper preserves only metadata supported by its build. Separate subvolumes and files outside the configured root remain outside the operation.

Manual snapshots are single, read-only by Snapper’s default, with no cleanup algorithm assigned by this page. Existing Snapper timers and external operations continue to apply. Snapshots are not full-system images: separate subvolumes, including a separate /home, are not included. This version provides no full-system rollback, installation or creation of a Snapper configuration. Press p on a supported root configuration to inspect the known retention settings. Missing values are shown as Snapper defaults, while unknown keys are diagnostic only. Press e to edit a supported value. The confirmation shows the old and new values; after saving, the page reads the config again and verifies it. Press c to cycle cleanup algorithms and Enter to review and confirm one. Cleanup uses Snapper’s official algorithm; there is no exact preview, and the reported removed count is measured by comparing lists after execution. Arch Snapper 0.13.2 provides snapper-timeline.timer and snapper-cleanup.timer; timeline creation requires the timeline timer, and configured cleanup policies do not run without cleanup scheduling. The page reads unit state only and does not enable timers. Space limits require configured Btrfs qgroups and are not exposed here.

Pre-update snapshots

Section titled “Pre-update snapshots”

After reviewing and confirming an official package upgrade, the helper takes one single snapshot of the configured Btrfs root immediately before pacman runs. This covers full upgrades, individual official package updates, and the full upgrade offered after adding a repository. Search, update checks, transaction planning, repository metadata refresh, AUR/yay operations and other package actions are not covered. A missing/unsupported root Snapper configuration or a snapshot creation error blocks the update; there is no continue-without-snapshot bypass. If pacman fails, the snapshot is retained and its ID is included in the error. If the helper is interrupted after starting pacman, the outcome is reported as indeterminate and package state should be checked before retrying. Only one ARGVUS protected upgrade can run at a time. The snapshot is a point in time for the configured root subvolume, not a guarantee that ESP, separate subvolumes, external data or application databases can be recovered. It has no cleanup algorithm assigned and can remain until a user runs Snapper cleanup.

Manual validation

Section titled “Manual validation”
  • On an ext4/xfs root, open the page in English and Portuguese. In Portuguese, verify the exact message Este sistema de arquivos não é Btrfs and verify that c/d do not open an operation.
  • In a disposable Btrfs VM, test Snapper absent, Snapper without a root configuration, and a configuration named root pointing to another subvolume.
  • With an existing root configuration, list snapshots, open details, create a snapshot with spaces/special characters, cancel a deletion, then delete only the newly created snapshot after confirming its number and description.
  • Check denied/cancelled authentication, protected active/default snapshots, refresh, keyboard navigation, resize and both languages. Do not test deletion against snapshots needed for recovery.

Only the argvus package changes. Rebuild from de/argvus with make build to produce the .pkg.tar.zst package; installing it is a separate operator action.

Language under Language & Region saves the locale in the user profile (~/.config/locale.conf) without changing /etc/locale.conf. The session uses this preference after login again. During Welcome, F6 Next or the footer Next button records review and advances; Shift+Tab focuses the button and Enter activates it, including on information pages.

Bluetooth appears in Welcome only when Control Center detects an adapter. Existing progress for a hidden Bluetooth step is preserved.

Language and the session keyboard layout are personal preferences and do not require administrator privileges. New profiles default to English and the US keyboard layout; existing personal preferences are preserved. Date/time, NTP, system locale generation and the console (TTY) keymap retain their system-wide administrative behavior.

For a Brazilian session keyboard, select br, apply the layout, then select abnt2 under Variant. This writes the personal Hyprland configuration without administrative authorization; the console keymap is separate. Window wobble

Section titled “Window wobble”

Open Desktop & Input → Hyprland → Animations → Windows and use the Wobble controls. Search for wobble, or open the page directly:

Wobble is disabled by default. Its ARGVUS defaults are stiffness 100, damping 10, mass 1, intensity 1 and mesh resolution 8. Stiffness and mass accept 0.0001–1000, damping 0–1000, intensity 0–2, and mesh an integer 2–32. Higher mesh resolution increases rendering cost. Use the arrow keys to adjust values or Enter to type them. Restore Wobble defaults changes the draft; Apply saves all pending animation edits and reloads Hyprland once, without restarting the session. Going back within Animations keeps the shared draft.

The global Animations switch suppresses Wobble while retaining its individual settings. The canonical values live under effects.wobble_* in ARGVUS state; hypr/state.lua is generated and must not be edited manually.

This requires Hyprland 0.57.0 or newer, enforced by argvus-hyprland’s package dependency. Version 0.56 is unsupported for this configuration. The intensity maximum follows the released 0.57.0 source, which limits it to 2, even though newer documentation may list 3.

Welcome opens with the ARGVUS logo and WELCOME. Press F6 Next to show the checklist without completing a step.

Fresh installations default to the personal time zone America/New_York and only the us keyboard layout enabled. Existing personal settings are preserved; the system time zone is unchanged.

Taskbar module options for Battery and Bluetooth appear only when the corresponding hardware is detected. Hiding Keep awake hides its indicator without changing the suspension inhibitor. Utilities supports a collapsed hover drawer. Workspace icon presentation displays icons for open windows; the system tray controls background application icons.

The keyboard shortcuts page includes AI agent selector (optional argvus-ai package) with default SUPER + A. It uses the app.ai catalog ID, so remapping and disabling follow the same canonical keyboard_shortcuts configuration as other entries. Its executable Lua bind is supplied by argvus-ai; the catalog entry alone does not activate it without that optional package.

Control Center > Appearance > Taskbar > Icons > Optional modules now includes AI Agents. It defaults to enabled and is stored in /taskbar/icons/ai_agents_enabled. Toggle it in the taskbar draft and Apply to persist and regenerate the utility group; disabling it does not change the SUPER + A shortcut or application launcher entries.
