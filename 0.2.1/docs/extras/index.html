ARGVUS Extras

This content is for v0.2.1. Switch to the latest version for up-to-date documentation.

argvus-extras does not contain the projects it distributes. It holds PKGBUILDs for third-party software that ARGVUS repackages and publishes into a separate extras Arch repository. Continuous integration compiles every package and publishes the artifacts to argvus/packages under public/arch/extras/x86_64/, indexed with repo-add (argvus-extras.db/.files).

If you use ARGVUS, the extras packages appear as normal Arch packages served from the ARGVUS repository:

Package inventory

Section titled “Package inventory”
Repo package Upstream Purpose
argvus-pwvucontrol (v0.5.3-2) saivert/pwvucontrol “Pipewire volume control for GNOME” — GTK4/libadwaita/wireplumber volume mixer. Provides/conflicts with pwvucontrol; binary pwvucontrol.
argvus-snappy-switcher (v4.0.0-1) OpalAayan/snappy-switcher Fast, animated Alt+Tab window switcher for Hyprland (MRU, context grouping). Binaries snappy-switcher, snappy-wrapper, snappy-install-config; config /etc/xdg/snappy-switcher/config.ini; optional systemd user unit.

argvus-pwvucontrol is the volume applet used by the desktop’s volume actions; argvus-snappy-switcher is the window switcher used by the taskbar Alt+Tab.

How publishing works

Section titled “How publishing works”
  1. CI discovers every packages/*/PKGBUILD.
  2. Each package is built in an archlinux:base-devel container.
  3. Artifacts are published with PACKAGES_REPO_TOKEN to the argvus/packages repository. Historic versions are preserved (no cleanup).
  4. Optional GPG_PRIVATE_KEY / GPG_PASSPHRASE secret values sign the packages.

Development notes

Section titled “Development notes”
  • make-style validation and local Docker builds are documented in the repository’s DEVELOPMENT.md.
  • The src/build and pkg/ directories you may find locally are build artifacts (cargo home, .zst packages) and are ignorable.
